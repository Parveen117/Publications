\hypertarget{byte-preservation-rule}{%
\section{Byte-preservation rule}\label{byte-preservation-rule}}

Files consumed by source-pin checks are copied without semantic renaming. Paths, historical namespaces, and line content remain source-identical to the imported commit.

Cross-platform verifier code canonicalizes text line endings before Git-blob hashing so a clean Windows or Unix checkout verifies the same pinned source content.

\hypertarget{public-overlay}{%
\section{Public overlay}\label{public-overlay}}

Public-facing documents in this repository are a reviewer overlay. They explain the imported cartridge under the Recognition Kernel Framework and RNKE terminology. The overlay does not change the imported mathematical source identity.

\hypertarget{excluded-material}{%
\section{Excluded material}\label{excluded-material}}

The public export excludes:

\begin{verbatim}
private filing drafts;
correspondence addresses;
priority-application lists;
private notebooks;
cache and build directories;
local machine paths;
credentials and tokens;
unreviewed experimental branches;
unrelated private repository history.
\end{verbatim}

\hypertarget{change-rule}{%
\section{Change rule}\label{change-rule}}

Any modification to a pinned theorem source, implementation source, package specification, or verifier requires:

\begin{verbatim}
new source pins;
new package version;
new result JSON;
new campaign hash;
updated claim boundary;
reproduction on a clean checkout.
\end{verbatim}

An old PASS artifact must never be presented as certifying modified sources.
